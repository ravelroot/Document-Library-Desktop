Capítulo 01

Visão rápida

O Lume para Windows guarda tudo num único arquivo SQLite, o lume.db, dentro da pasta de dados. Este manual descreve o esquema, as regras que o banco garante sozinho, a busca, as consultas por trás das telas novas e como fazer backup, verificar e evoluir o banco.

11tabelas10 comuns + 1 virtual FTS5
92colunas33 só em documents
8chaves estrangeirastodas ON DELETE CASCADE
20índices10 declarados · 10 de PK/UNIQUE
22restrições CHECKdomínios, faixas e json_valid
2migraçõesPRAGMA user_version = 2
5chaves em settingsprofile · ai · window · watch_folders · webhooks
0tabelas novas na 2.1.0integrações em settings

Onde cada coisa mora

lume.db · fonte da verdade
  • Documentos, metadados, sumário, descrição por IA e texto extraído.
  • Índice de busca FTS5.
  • Etiquetas, coleções, estantes, progresso e anotações.
  • Histórico de cada etapa do pipeline.
  • Preferências, chave de IA cifrada, pastas monitoradas e webhooks.
Memória do processo · transporte
  • Filas de leitura e descrição (ExecutorService).
  • Novas tentativas agendadas (5 s, 15 s, 45 s).
  • Eventos ao vivo (SSE) e envio de webhooks.
  • Agendador das pastas monitoradas e a lista de arquivos já recusados.
documentos/ · arquivos
  • Cópia do original, sem alteração.
  • Capa em JPEG.
  • HTML de leitura higienizado e imagens dos DOCX.
  • Importações e backups em andamento em tmp/.
Regra de ouro Fechar o Lume no meio de um trabalho não perde dados: o que estava em memória é refeito a partir do banco na próxima abertura. Perder o lume.db ou a pasta documentos/ perde dados — por isso o backup da 2.1.0 leva os dois juntos (capítulo 10).

Para quem é este documento

Para quem usa, mantém ou desenvolve o Lume: a referência de cada tabela e coluna, as regras que o banco e a aplicação garantem e as tarefas de rotina (consultas, verificação, backup, restauração e migrações). Tipos, nulos e padrões das fichas foram lidos do próprio esquema (Migrations.java), que é a fonte da verdade.

Capítulo 02

Visão geral

Um banco embutido, sem servidor, aberto por uma conexão só e protegido por restrições: é o suficiente para uma biblioteca pessoal e cabe num pendrive.

Por que SQLite

  • Zero instalação: o SQLite vem dentro do próprio Lume, no driver JDBC sqlite-jdbc 3.53 (Xerial), que já traz o motor compilado com FTS5 e JSON. Não há servidor, porta nem senha.
  • Um usuário, um computador: o Lume desktop não tem contas nem compartilhamento, então a concorrência é baixa e o SQLite sobra.
  • Portátil: copiar a pasta de dados (ou um backup em zip) leva a biblioteca inteira para outro computador ou para um pendrive.
  • Busca embutida: o FTS5 faz a busca em texto completo sem acentos, com ranking BM25 e trechos destacados.
  • Compatível: o esquema é o mesmo desde a versão em Electron (esquema 2). A 2.1.0 não muda o esquema: as integrações ficam na tabela settings.

Como o banco é aberto

A classe Database (pacote io.github.ravelroot.lume.db) abre uma conexão JDBC só, jdbc:sqlite:<pasta>/lume.db, e liga o modo de trabalho:

PRAGMA journal_mode = WAL;      -- leituras não esperam escritas; grava lume.db-wal ao lado
PRAGMA synchronous = NORMAL;    -- seguro com WAL e bem mais rápido que FULL
PRAGMA foreign_keys = ON;       -- o SQLite só aplica chaves estrangeiras com isto ligado
PRAGMA busy_timeout = 5000;     -- espera até 5 s se o arquivo estiver ocupado

Em seguida migrate() compara PRAGMA user_version com a lista Migrations.ALL e aplica as que faltam, cada uma numa transação. Se o banco tiver uma versão maior que a do aplicativo (foi aberto por um Lume mais novo), a abertura é recusada com uma mensagem clara. Ao fechar, o Lume faz PRAGMA wal_checkpoint(TRUNCATE), devolvendo tudo para o lume.db.

As consultas passam pelo JdbcTemplate do Spring, sobre um SingleConnectionDataSource. Uma trava (ReentrantLock) garante que a API, o pipeline, as pastas monitoradas, os webhooks e as ferramentas usem a conexão um de cada vez.

Capítulo 03

Diagrama de relacionamentos

As 11 tabelas giram em torno de documents. Todas as chaves estrangeiras usam ON DELETE CASCADE: apagar um documento apaga o texto, a leitura, as anotações, as etiquetas ligadas, os itens de coleção e o histórico de etapas.

O pé de galinha fica do lado “muitos” e o traço duplo do lado “um”. Cada caixa mostra as colunas principais; as fichas do capítulo 04 trazem todas. A faixa colorida indica a área: Acervo Organização Leitura Sistema. A tabela virtual documents_fts não tem chave estrangeira: a ligação é mantida pela aplicação.

Convenções e tipos

  • Datas: texto ISO 8601 em UTC (2026-10-27T13:00:00.315Z, gerado por Times.now()), que ordena corretamente como texto e permite substr(created_at, 1, 7) para agrupar por mês.
  • Booleanos: INTEGER 0 ou 1 com CHECK.
  • JSON: campos estruturados (sumário, metadados, posição de leitura, âncora, detalhes da etapa, preferências) são texto validado com CHECK (json_valid(...)), lidos com o Jackson e consultados com json_extract.
  • Identificadores: UUID v4 em TEXT para documentos, coleções e anotações; INTEGER PRIMARY KEY (rowid) para etiquetas e etapas.
  • Nomes: tabelas no plural, colunas em snake_case, índices <tabela>_<coluna>.

As duas listas são lidas e regravadas inteiras a cada mudança (INSERT … ON CONFLICT (key) DO UPDATE), dentro da trava da conexão. A API nunca devolve o segredo: GET /api/v1/integrations mostra só has_secret. O que não é guardado de propósito: a lista de arquivos já recusados pelas pastas monitoradas (fica em memória e recomeça a cada abertura) e o histórico de envios dos webhooks (só o último resultado fica salvo).

Consultar à mão
SELECT json_extract(value, '$[0].path'), json_array_length(value) FROM settings WHERE key = 'watch_folders';
SELECT json_extract(h.value, '$.url'), json_extract(h.value, '$.last_status')
  FROM settings s, json_each(s.value) h WHERE s.key = 'webhooks';
Capítulo 06

Ciclo de vida e estados

Três colunas funcionam como pequenas máquinas de estado: o estado do documento, o de cada etapa e a estante. Quem muda o estado do documento é sempre o PipelineService, numa transação, e cada mudança vira um evento para a tela.

TransiçãoOndeO que é gravado
importação → queuedLibraryService.importFileLinha nova, arquivo em documentos/<id>, entrada no índice de busca; evento document.created
queued → extractingPipelineService.claimattempts + 1; só pega quem está no estado esperado (pedido repetido não faz nada)
extracting → describingapplyExtractionPáginas, palavras, sumário, metadados, capa (cover_version + 1), texto em document_content, índice de busca
describing → readyrunDescribeDescrição, origem, modelo, idioma, etiquetas da IA, processed_at na primeira vez; evento document.ready
falha passageira → queuedrunExtractstatus_detail “Nova tentativa em 5 s”; etapa retrying
falha definitiva → failedfailstatus_detail com a mensagem; etapa failed
lote reprocess · redescribeBatchService · ToolsServiceVolta para a fila de leitura ou de descrição (inclusive “Descrever tudo de novo”)
Recuperação ao abrirQuando o Spring termina de subir (ApplicationReadyEvent), recover() marca como failed as etapas que ficaram running, devolve para a fila de leitura os documentos em queued ou extracting e para a fila de descrição os que estavam em describing.
Capítulo 07

Busca em texto completo

A busca usa a tabela virtual FTS5 com uma linha por documento. A mesma tabela serve à paleta de comandos e ao “Parecidos na sua biblioteca”; o “Pergunte ao documento” lê o texto em document_content.

CREATE VIRTUAL TABLE documents_fts USING fts5 (
  document_id UNINDEXED,     -- liga a linha ao documento (não é pesquisado)
  title,                     -- peso 10
  author,                    -- peso 5
  extra,                     -- descrição por IA + sua descrição + etiquetas, peso 3
  body,                      -- os primeiros 300.000 caracteres do texto, peso 1
  tokenize = 'unicode61 remove_diacritics 2'
);

SearchService.refreshSearch(id) apaga e reinsere a linha do documento; ele roda na importação, depois da leitura, depois da descrição, ao editar título, autor ou descrição e ao trocar etiquetas (inclusive em lote), sempre dentro da mesma transação da mudança. Ferramentas → Reconstruir o índice de busca faz isso para todos os documentos e compacta o índice.

Da caixa de busca para o MATCH

Você digitaViraPor quê
contrato aluguel"contrato"* AND "aluguel"*todas as palavras, aceitando o começo
"reunião de planejamento""reunião de planejamento"frase exata
python -flask"python"* NOT "flask"*exclusão
a"b OR"a" AND "b" AND "or"*aspas e operadores digitados viram texto: a consulta nunca quebra

Além do MATCH, a listagem aceita documentos cujo title_sort contenha o texto digitado (LIKE), para achar pedaços no meio de palavras do título. O filtro de etiqueta junta document_tags e tags pelo slug.

Ranking e trecho

SELECT d.*
FROM documents d
LEFT JOIN (SELECT document_id, bm25(documents_fts, 0, 10.0, 5.0, 3.0, 1.0) AS rank
           FROM documents_fts WHERE documents_fts MATCH :consulta) f ON f.document_id = d.id
WHERE (f.document_id IS NOT NULL OR d.title_sort LIKE :trecho ESCAPE '\')
ORDER BY (f.rank IS NULL), f.rank, d.created_at DESC
LIMIT :tamanho OFFSET :inicio;

-- trecho com a palavra destacada, só para os documentos da página
SELECT document_id, snippet(documents_fts, 4, char(2), char(3), ' … ', 26)
FROM documents_fts WHERE documents_fts MATCH :consulta AND document_id IN (...);

O BM25 do FTS5 devolve números menores para os melhores resultados; os pesos fazem o título valer mais que o texto. O trecho usa os caracteres de controle 2 e 3 como marcadores: o texto é escapado para HTML e só então eles viram <mark>, então nada do documento vira HTML na tela.

Parecidos e Pergunte 2.1.0

Parecidos na sua biblioteca (DiscoveryService) soma duas pistas: etiquetas em comum (cada etiqueta compartilhada vale 3 pontos, ou 4 quando, no outro documento, ela foi escolhida pela pessoa) e uma busca FTS com os termos do título e das etiquetas do documento ligados por OR (o 1º resultado vale 2,5 pontos e o valor cai até o 30º). Só entram documentos prontos, sem o próprio, em ordem de pontuação.

-- etiquetas em comum com o documento :id
SELECT other.document_id AS id,
       sum(CASE WHEN other.source = 'usuario' THEN 4.0 ELSE 3.0 END) AS s
FROM document_tags mine
JOIN document_tags other ON other.tag_id = mine.tag_id AND other.document_id != mine.document_id
WHERE mine.document_id = :id
GROUP BY other.document_id;

-- termos do título e das etiquetas no índice ("termo"* a partir de 5 letras)
SELECT document_id FROM documents_fts
WHERE documents_fts MATCH '"python"* OR "guia" OR "programacao"*' AND document_id != :id
ORDER BY bm25(documents_fts, 0, 10.0, 5.0, 3.0, 1.0) LIMIT 30;

O Pergunte ao documento não usa o FTS: lê document_content.text do documento, divide em trechos de 400 a 700 caracteres (a página vem da contagem de \f no PDF) e pontua os trechos com um BM25 próprio em memória (PassageFinder). Nada é gravado: perguntas e respostas não ficam no banco.

Capítulo 08

Integridade e transações

As regras importantes ficam no próprio banco, não só no código: mesmo um script que escreva direto no lume.db não consegue gravar um estado inválido.

RegraComo o banco garante
Um arquivo, um documentosha256 UNIQUE em documents; duas importações simultâneas do mesmo arquivo (por exemplo, a pasta monitorada e um arrastar): a segunda vira “duplicado”
Valores dentro do domínioCHECK em kind, status, shelf, color, stage, booleanos, progress, page, size_bytes
JSON válidoCHECK (json_valid(...)) em outline, metadata, location, anchor, details e value (inclusive as listas de integrações)
Sem órfãosFOREIGN KEY ... ON DELETE CASCADE em todas as tabelas filhas, com PRAGMA foreign_keys = ON
Nomes de coleção únicosUNIQUE INDEX ON collections (lower(name))
Uma ligação por parChaves primárias compostas em document_tags e collection_items

Transações

Database.transaction(...) recebe um Runnable ou Supplier: a primeira chamada abre BEGIN IMMEDIATE (reserva a escrita na hora, evitando conflito no meio) e chamadas aninhadas viram SAVEPOINT. Se qualquer coisa lançar exceção, tudo é desfeito (ROLLBACK ou ROLLBACK TO).

db.transaction(() -> {
    db.update("INSERT INTO documents (...) VALUES (...)", ...);
    Files.move(tmp, pasta.resolve("original." + kind));      // falhou? a linha também volta
    search.refreshSearch(id);                               // SAVEPOINT aninhado
});

Ações em lote 2.1.0

POST /api/v1/documents/batch (BatchService) recebe até 500 ids, descarta repetidos e os que não existem e aplica a ação documento por documento, com os mesmos serviços das ações individuais: ReadingService para estante e favorito, LibraryService.setTags para etiquetas (somando às da pessoa, sem tocar nas da IA), CollectionService para coleções, deleteDocument para exclusão e o pipeline para reler ou redescrever. Cada documento é gravado pelas transações do próprio serviço (não há uma transação única para o lote): o que já foi aplicado continua valendo se um item falhar, e os eventos e webhooks saem como sempre.

ConcorrênciaSó o processo do Lume escreve no banco, por uma conexão só, protegida por uma trava (ReentrantLock). Os fios da API (Tomcat), do pipeline, das pastas monitoradas, dos webhooks e das ferramentas esperam a vez, então não há disputa, e o modo WAL deixa leituras externas correrem enquanto o pipeline grava. Operações longas, como VACUUM, seguram a trava só pelo tempo da instrução.

Capítulo 10

Backup, restauração e manutenção

A biblioteca é o banco mais a pasta documentos/. Na 2.1.0, as duas coisas saem juntas num .zip pela tela Ferramentas, e as tarefas de manutenção que antes exigiam o sqlite3 viraram botões.

Backup pelo Lume 2.1.0

  1. Instantâneo consistente: ToolsService.backupTo roda VACUUM INTO 'tmp/…/lume.db', que grava uma cópia compacta e coerente do banco sem fechar a conexão e sem parar o Lume.
  2. Zip: o arquivo escolhido no diálogo recebe lume.db (o instantâneo), documentos/** (só as pastas de documentos que existem no banco) e LEIAME.txt com a data, a versão, a contagem e as instruções. O zip é gravado primeiro com outro nome e só renomeado no fim: um backup interrompido não deixa um arquivo pela metade.
  3. Limpeza: o instantâneo temporário é apagado.

Sem o Lume aberto, o jeito manual continua valendo: com o aplicativo fechado (o diário WAL é incorporado ao lume.db), copie a pasta de dados inteira.

Restauração e mudança de computador

  1. Feche o Lume.
  2. Abra a pasta de dados (%APPDATA%\Lume\Biblioteca, Lume-dados\Biblioteca no modo portátil ou LUME_DATA_DIR).
  3. Guarde (ou apague) lume.db, lume.db-wal, lume.db-shm e documentos.
  4. Extraia o zip ali dentro e abra o Lume. Se o backup veio de uma versão mais antiga, as migrações que faltam rodam na abertura.
Segredos não viajamA chave de API (settings.ai.api_key) e os segredos dos webhooks (settings.webhooks[].secret) são cifrados pelo DPAPI para a conta do Windows que os gravou. Em outro computador ou outra conta eles não abrem: informe de novo em Preferências e em Integrações. As pastas monitoradas restauradas apontam para caminhos do computador antigo; confira-as em Integrações.

Capítulo 11

Evolução do esquema e versão web

Como mudar o banco sem perder dados e como ele se compara ao PostgreSQL da versão web.

Criar uma migração

  1. Acrescente um texto SQL no fim da lista ALL em src/main/java/io/github/ravelroot/lume/db/Migrations.java. Nunca edite migrações já publicadas.
  2. Prefira mudanças aditivas: ALTER TABLE ... ADD COLUMN com DEFAULT, tabelas e índices novos. Dados pequenos de configuração podem ir para settings, como as integrações da 2.1.0, sem migração nenhuma.
  3. Para mudar o tipo ou as restrições de uma coluna, siga o roteiro do SQLite: criar a tabela nova, copiar com INSERT ... SELECT, apagar a antiga e renomear, tudo na mesma migração (a migração 2 faz exatamente isso com as cores das anotações).
  4. Rode mvn test: o DatabaseTest abre um banco vazio, confere as tabelas, abre de novo para garantir que nada é reaplicado e testa a migração de um banco no esquema 1.
// src/main/java/io/github/ravelroot/lume/db/Migrations.java
static final String V3 = """
        ALTER TABLE reading_states ADD COLUMN seconds_read INTEGER NOT NULL DEFAULT 0;
        """;    // 3: exemplo — tempo total de leitura
public static final List<String> ALL = List.of(V1, V2, V3);
