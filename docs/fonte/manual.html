Capítulo 01

Visão rápida

O Lume para Windows em uma página: o que é, para quem foi feito e como as peças se encaixam.

O que é

Uma biblioteca pessoal de PDF e DOCX que roda inteira no seu computador, num único Lume.exe, sem instalador, sem servidor na nuvem e sem conta. Cada arquivo importado ganha capa, texto indexado, sumário, descrição e etiquetas escritas por IA, e abre num leitor próprio que guarda a página, os destaques e as notas.

Para quem
  • Quem acumula apostilas, livros técnicos, artigos, relatórios, contratos e atas e quer tudo num lugar só, com busca no texto.
  • Pesquisadores e estudantes que levam o catálogo para o Zotero, o Obsidian ou uma planilha.
  • Desenvolvedores que querem estudar uma aplicação desktop em Java 21 com Spring Boot e SQLite.
Da pasta à leitura
01 · ImportarArraste arquivos ou pastas, use o botão ou deixe uma pasta monitorada. Repetidos são reconhecidos pelo SHA-256.
02 · LerO núcleo Java (PDFBox e o leitor de DOCX) extrai texto, sumário e metadados e desenha a capa.
03 · DescreverO resumo local ou o provedor de IA escreve a descrição e sugere etiquetas.
04 · ProntoA tela se atualiza sozinha (Server-Sent Events) e os webhooks avisam outros sistemas.
05 · UsarLeia, destaque, pergunte ao documento, organize em lote e exporte para outros programas.
Como começar

Baixe o Lume.exe (cerca de 46 MB, com o Java embutido) e dê dois cliques. Na primeira vez o Windows pode pedir Mais informações → Executar assim mesmo. Arraste a pasta exemplos/ do repositório para ver a biblioteca cheia.

Privacidade

Por padrão tudo acontece no computador: o resumo e as respostas são feitos localmente e nenhum trecho sai da máquina. Provedores externos de IA e webhooks são opcionais e só enviam o que está descrito nos capítulos 06 e 07.

Capítulo 02

Visão geral

O Lume para Windows é a versão desktop do Lume web: a mesma interface, a mesma lógica de biblioteca e o mesmo leitor, com o núcleo em Java 21 e Spring Boot e todos os dados numa pasta do seu usuário.

Para que serve

O Lume funciona como uma estante digital instalada no próprio computador. Você arrasta os arquivos (ou pastas inteiras) para a janela e cada documento ganha capa, descrição escrita por IA, sumário e um leitor que lembra onde você parou. Serve para organizar apostilas, livros técnicos, artigos, relatórios, contratos e atas com busca no texto completo, estantes de leitura, coleções e anotações, e para levar esse acervo a outros programas quando for preciso.

Não há servidor na internet, Docker nem conta: tudo fica num executável, o Lume.exe, e numa pasta de dados no seu usuário do Windows (ou num pendrive, no modo portátil).

Capítulo 03

Instalação e primeira execução

Não há instalador: o Lume é um único arquivo. Basta abrir o Lume.exe. Na primeira vez o Windows pode pedir uma confirmação, porque o arquivo não tem assinatura digital paga.

Requisitos

  • Windows 10 ou 11, 64 bits, com o Microsoft Edge (já vem com o Windows). O Java vai dentro do Lume.exe: não é preciso instalar nada.
  • Cerca de 300 MB livres: na primeira abertura o Lume.exe extrai o Java reduzido e o aplicativo para %LOCALAPPDATA%\Lume\app\<versão>; as aberturas seguintes reaproveitam essa pasta.
  • Espaço para os seus documentos: o Lume guarda uma cópia de cada arquivo importado.
  • Internet só se você escolher um provedor de IA externo ou cadastrar webhooks. O resto funciona desconectado.

Abrir pela primeira vez

  1. Copie o Lume.exe para onde quiser (Área de Trabalho, Documentos, um pendrive).
  2. Dê dois cliques nele. Se aparecer O Windows protegeu o computador, clique em Mais informações e depois em Executar assim mesmo. Isso só acontece na primeira vez.
  3. Espere alguns segundos: na primeira vez o lançador prepara o Java e o aplicativo; depois o Spring Boot sobe e a janela do Lume abre no Edge, em modo aplicativo (sem barra de endereço).
  4. A biblioteca abre vazia. Arraste PDFs, DOCX ou uma pasta para a janela, use Adicionar documentos ou cadastre uma pasta monitorada em Integrações.
Experimente com os exemplosO repositório traz a pasta exemplos/ com 12 documentos fictícios (8 PDF e 4 DOCX). Arraste a pasta inteira para a janela para ver a biblioteca cheia, como nos prints deste manual.

Onde ficam os dados

SituaçãoPasta
Padrão%APPDATA%\Lume\Biblioteca (por exemplo C:\Users\voce\AppData\Roaming\Lume\Biblioteca), a mesma das versões anteriores, então a biblioteca continua lá

Dentro da pasta ficam o banco lume.db (e os arquivos auxiliares lume.db-wal e lume.db-shm), a pasta documentos\ com uma subpasta por documento (original, capa, HTML de leitura e imagens), a pasta tmp\, usada durante a importação e o backup, e o registro lume.log. As pastas monitoradas e os webhooks ficam guardados no próprio banco, na tabela de preferências. O perfil da janela (cache do Edge) fica em %LOCALAPPDATA%\Lume\navegador. O botão Abrir a pasta de dados, em Sistema, em Preferências e na paleta de comandos, abre o lugar certo no Explorador.

Modo portátil

Para levar a biblioteca num pendrive, crie uma pasta chamada exatamente Lume-dados ao lado do Lume.exe antes de abrir. A partir daí, banco, documentos e o perfil da janela ficam dentro dela (Lume-dados\Biblioteca e Lume-dados\app). A tela Sistema mostra Portátil quando esse modo está ativo.

Atualizar, backup e desinstalar

  • Atualizar: feche o Lume e troque o Lume.exe pelo novo. A pasta de dados continua a mesma; a 2.1.0 não muda o esquema do banco, então uma biblioteca da 2.0 abre direto. Quem vem da versão 1 (Electron) só precisa informar de novo a chave de API, se usava um provedor externo.
  • Backup: em Ferramentas → Backup completo, com o Lume aberto, gere um .zip com o banco e todos os arquivos (veja Backup completo). Com o Lume fechado, copiar a pasta de dados inteira também funciona.
  • Desinstalar: apague o Lume.exe, a pasta %LOCALAPPDATA%\Lume e, se quiser apagar também a biblioteca, a pasta %APPDATA%\Lume. Os arquivos de onde você importou os documentos nunca são alterados.
Capítulo 04

Guia das telas

A janela tem o menu lateral à esquerda (biblioteca, estantes, estatísticas, coleções, ferramentas, integrações, sistema e preferências) e, no alto, a busca, o botão Comandos e o botão de adicionar. O leitor ocupa a janela inteira.

Biblioteca

Tela inicial · /
  • Cabeçalho: a data, a saudação e um resumo em uma frase com os números reais (documentos, em leitura, sendo preparados e com erro). À direita, o livro-caixa das estantes: Quero ler, Lendo e Lidos.
  • Continuar lendo mostra os últimos documentos abertos que ainda não foram marcados como lidos, com a página e o progresso.
  • Filtros em abas: Todos, PDF, DOCX, Quero ler, Lendo, Lidos, Favoritos e, quando houver, Processando e Com erro, com contadores.
  • Etiquetas 2.1.0: abre a lista das etiquetas em uso (com a contagem) e filtra a biblioteca por uma delas; o filtro ativo aparece logo abaixo da barra, com um × para tirar.
  • Selecionar 2.1.0: liga a seleção múltipla (veja a próxima seção).
  • Ordem: adicionados recentemente, lidos recentemente, título, autor, mais páginas, maior tamanho e, numa busca, mais relevantes; dentro de uma coleção, a ordem da coleção.
  • Grade ou lista: alterna entre cartões com capa e uma tabela compacta (com caixas de seleção); a escolha fica guardada.
  • Favorito: a estrela no canto da capa marca e desmarca sem abrir o documento. Arrastar para coleção: solte um cartão sobre o nome de uma coleção no menu lateral.

Seleção e ações em lote 2.1.0

Atalho S

Para agir sobre vários documentos de uma vez, ligue a seleção com o botão Selecionar, com a tecla S ou com Shift + clique num cartão. Cada capa ganha uma caixa no canto; com a seleção ligada, clicar no cartão marca e desmarca em vez de abrir. Na visualização em lista, cada linha tem uma caixa e o cabeçalho seleciona todos.

Botão da barraO que faz
TodosMarca (ou desmarca) todos os documentos carregados na tela. Também com Ctrl A.
EstanteQuero ler, Lendo, Lido ou tirar da estante.
ColeçãoAdicionar a uma coleção existente, criar uma nova e já adicionar, ou (dentro de uma coleção) tirar dela.
MaisFavoritar ou tirar dos favoritos; adicionar etiquetas (somam às que cada documento já tem); gerar a descrição de novo; ler os arquivos de novo; exportar só a seleção em CSV, JSON, BibTeX ou Markdown.
ExcluirTira os documentos da biblioteca, depois de confirmar. Os arquivos originais continuam onde estavam.

Todas as ações usam uma única chamada à API (POST /api/v1/documents/batch, até 500 documentos), aplicada pelo núcleo com os mesmos serviços das ações individuais: os eventos ao vivo, os contadores e os webhooks continuam funcionando.

Paleta de comandos 2.1.0

Ctrl K

Ctrl K (ou o botão Comandos na barra superior) abre uma caixa única para fazer tudo pelo teclado. Digite parte de um nome, sem se preocupar com acentos:

  • Documentos: a partir de duas letras, a paleta busca no título, no autor, nas etiquetas e no texto completo e mostra os seis melhores, com a capa. Enter abre os detalhes.
  • Coleções: abre a coleção pelo nome.
  • Ir para: Biblioteca, Estantes, Coleções, Estatísticas, Ferramentas, Integrações, Sistema e Preferências.
  • Ações: adicionar documentos, importar uma pasta, nova coleção, selecionar documentos, backup completo, exportar o catálogo em cada formato e abrir a pasta de dados.
  • Aparência e ajuda: tema igual ao Windows, claro ou escuro; lista de atalhos.
  • A última linha, Buscar “…” na biblioteca, leva a busca para a grade, com filtros e ordenação.

Use ↑ ↓ para escolher, Enter para executar e Esc para fechar.

Prévia ao passar o mouse

Descrição por IA

Pare o mouse sobre um cartão por um instante e a prévia abre ao lado: tipo, número de páginas, tamanho, estante, a descrição por IA (com a indicação de quem escreveu), as etiquetas e os botões Ler agora (ou Continuar) e Detalhes.

Ela também abre com o teclado, ao focar o cartão com Tab, e fica desligada enquanto a seleção em lote está ativa.

Adicionar documentos

Atalho U

Quatro jeitos, todos com o mesmo resultado:

  1. Arrastar arquivos ou pastas do Explorador para qualquer lugar da janela. Os arquivos soltos são enviados ao núcleo Java pela própria janela (rota /api/v1/desktop/upload).
  2. Adicionar documentos, no alto (ou U), abre o seletor de arquivos do Windows. Nesse caso o Lume copia direto do disco, pelo caminho.
  3. A seta ao lado do botão oferece Importar uma pasta inteira, que procura PDFs e DOCX em todas as subpastas.
  4. Pastas monitoradas 2.1.0: em Integrações, escolha pastas (Downloads, OneDrive, scanner) cujos arquivos novos entram sozinhos (veja o capítulo 07).

Cada arquivo é copiado para a pasta da biblioteca, com a impressão digital calculada no caminho; o original fica intocado. Se a mesma impressão digital já existir, o item aparece como Já estava na sua biblioteca. Arquivos .doc antigos, planilhas, arquivos vazios ou com conteúdo que não corresponde à extensão são recusados com a explicação na bandeja. O limite é de 500 MB por arquivo. Se você estiver dentro de uma coleção, o que for importado já entra nela.

Também dá para abrir arquivos direto no Lume: arraste PDFs ou DOCX sobre o ícone do Lume.exe ou use Abrir com no Explorador. Se o Lume já estiver aberto, a janela existente recebe os arquivos e vem para a frente.

Busca e etiquetas

Atalho /

A busca procura no título, no autor, na descrição por IA, na sua descrição, nas etiquetas e no texto completo, sem diferenciar acentos nem maiúsculas. O trecho onde a palavra aparece vem destacado embaixo do cartão. Pressione / para ir à busca de qualquer tela, ou use a paleta (Ctrl K) para ver os melhores resultados sem sair da tela atual.

As etiquetas funcionam como um segundo filtro: clique numa etiqueta na página do documento ou escolha uma no botão Etiquetas da biblioteca. Busca, filtros e etiqueta se combinam.

Pergunte ao documento 2.1.0

POST /documents/{id}/ask

Na página de um documento pronto, escreva uma pergunta (de 3 a 500 caracteres) ou clique numa das sugestões: Qual é o assunto principal?, Quais são as conclusões?, Que datas e prazos aparecem?, Quais números são citados?

  • Sem internet (resumo automático): o Lume procura no texto os trechos que mais combinam com a pergunta e mostra o melhor em destaque, seguido dos outros, numerados.
  • Com um provedor de IA: os melhores trechos vão para o modelo, que escreve uma resposta curta em português citando os trechos como [1], [2]. Se o provedor falhar, a resposta cai para a busca local e o motivo aparece logo abaixo.
  • Em PDFs, cada trecho traz o link abrir na página N, que leva direto ao ponto no leitor.

Como configurar

  1. Abra Preferências → Inteligência artificial (ou Integrações → Configurar o provedor).
  2. Clique no cartão do provedor. Cole a chave de API, quando o serviço pedir; para Ollama e LM Studio basta o modelo instalado.
  3. Clique em Testar: o Lume pede a descrição de um texto curto e mostra o resultado (com o tempo) ou o erro.
  4. Clique em Salvar. Vale para os próximos documentos e para o “Pergunte”; para os que já existem, use Gerar de novo nos detalhes, a seleção em lote ou Ferramentas → Descrever tudo de novo.

Como o “Pergunte” responde 2.1.0

  1. Trechos: o texto do documento (guardado em document_content) é dividido em trechos de 400 a 700 caracteres, respeitando parágrafos; no PDF, cada trecho guarda a página (as páginas vêm separadas por \f).
  2. Pontuação: a pergunta vira termos sem acento e sem palavras vazias (português e inglês), com um radical simples; cada trecho recebe uma nota BM25 (PassageFinder, k1 = 1,4 e b = 0,72).
  3. Sem internet: a resposta são as frases do melhor trecho que mais combinam com a pergunta; os quatro melhores trechos aparecem numerados. Se nenhum trecho combina, o Lume diz isso e lembra o resumo do documento.
  4. Com provedor: os seis melhores trechos vão numerados para o modelo, com a instrução de responder em português, em no máximo cinco frases, usando só os trechos e citando [1], [2]. Se o provedor falhar, a resposta local assume e o aviso explica o motivo.

Dados enviados e chave

Para a descrição, vão só o título, o autor, o tipo, o número de páginas, até 30 títulos do sumário e um trecho do texto (por padrão até 12.000 caracteres: três quartos do começo e um quarto do meio). Para o “Pergunte”, vão o título, o autor, a pergunta e os seis trechos escolhidos. O arquivo original nunca é enviado. Com o resumo automático, nada sai do computador. As chamadas usam o cliente HTTP do próprio Java, que respeita o proxy do sistema.

Chave de APIA chave é cifrada com o cofre do Windows (DPAPI, chamado pelo Java via JNA) antes de ir para o banco, com o prefixo dpapi:; só o seu usuário do Windows consegue abrir. Ela não volta para a tela depois de salva e pode ser apagada em Preferências. Chaves salvas pela versão 1 (Electron) não abrem no Java: informe de novo.

Quando o provedor falha

Sem internet, chave errada, limite de uso ou resposta fora do formato: o Lume não deixa o documento parado. Ele usa o resumo automático e registra o motivo na etapa (veja em Sistema → Últimas etapas). Textos com menos de 200 caracteres, como PDFs digitalizados sem texto, vão direto para o resumo automático.

Integrações e exportação 2.1.0

Pastas monitoradas

Em Integrações → Adicionar pasta…, escolha até 10 pastas. Enquanto o Lume está aberto, o WatchFolderService verifica as pastas ativas a cada 60 segundos (a primeira verificação acontece cerca de 20 segundos depois de abrir) e importa os PDFs e DOCX novos, inclusive das subpastas, pelo mesmo caminho de uma importação normal.

  • Coleção de destino: o que entrar por aquela pasta pode ir direto para uma coleção.
  • Pausar: a chave de cada pasta suspende a verificação sem perder a configuração.
  • Verificar agora: varre todas as pastas na hora e mostra quantos documentos novos entraram.
  • Sem repetição: arquivos cujo caminho já é a origem de um documento são pulados; repetidos (mesmo SHA-256) e recusados ficam numa lista em memória pelo caminho, tamanho e data, e não são tentados de novo enquanto não mudarem.
  • Arquivo ainda sendo copiado: na verificação automática, arquivos alterados há menos de 5 segundos esperam a próxima rodada.
  • Quando algo entra, a janela mostra um aviso (“3 documentos novos de ‘Downloads’”) e os contadores se atualizam (evento watch.imported).

Assinatura e entrega

Com um segredo, cada envio leva o cabeçalho X-Lume-Signature: sha256=<HMAC-SHA256 do corpo>; quem recebe recalcula o HMAC com o mesmo segredo e descarta o que não confere. O segredo é guardado cifrado pelo cofre do Windows (DPAPI), como a chave da IA, e nunca volta para a tela.

# Conferir a assinatura (Python)
import hmac, hashlib
esperado = "sha256=" + hmac.new(SEGREDO.encode(), corpo_bruto, hashlib.sha256).hexdigest()
valido = hmac.compare_digest(esperado, request.headers["X-Lume-Signature"])

Os envios saem em segundo plano, um fio só para webhooks, com tempo limite de 10 segundos; o resultado (código HTTP ou erro) e a hora do último envio aparecem na linha do webhook. Testar manda na hora um evento de exemplo e mostra a resposta.

O caminho de um documento

  1. Importação (LibraryService.importFile): o arquivo é copiado para tmp\ calculando o SHA-256; o tipo é conferido pelo conteúdo (cabeçalho %PDF- ou zip com word/document.xml); se a impressão digital é nova, o documento é criado como queued e o arquivo vai para documentos\<id>\original.pdf. Evento document.created.
  2. Leitura (extract): PDFs vão para o PdfBoxProcessor, que devolve texto (páginas separadas por \f), sumário, metadados e a capa em JPEG; DOCX são lidos pelo DocxExtractor, que gera o HTML de leitura (higienizado), as imagens e a capa tipográfica.
  3. Descrição (describe): o texto vai para o provedor de IA escolhido; o resultado e as etiquetas são gravados e o índice de busca é atualizado.
  4. Pronto: cada mudança de etapa gera um evento (SSE) que atualiza a tela sozinha; ao terminar, o evento document.ready também dispara os webhooks.

Fila e recuperação

  • A leitura roda um documento por vez e a descrição até dois ao mesmo tempo, num ExecutorService, sem travar a interface.
  • O PDFBox trabalha num fio próprio com tempo limite (4 minutos por PDF, 30 segundos por capa). Se travar, o fio é abandonado e outro é criado.
  • Falhas passageiras tentam de novo com espera crescente: 5 s, 15 s, 45 s (ScheduledExecutorService). Depois da terceira, o documento fica Com erro. Falhas definitivas (PDF protegido por senha, arquivo corrompido, .doc antigo) vão direto para Com erro.
  • Se o Lume for fechado no meio, na próxima abertura o que estava pela metade volta para a fila. Cada etapa vira uma linha na tabela jobs: é o histórico da tela Sistema.
  • As pastas monitoradas e os webhooks têm fios próprios (um agendador e um enviador), separados do pipeline.

Segurança

  • Só no próprio computador: o Tomcat escuta apenas 127.0.0.1 (porta 47820 ou a próxima livre). Nada fica acessível pela rede.
  • Sessão da janela: o Lume abre a janela em /entrar?chave=… com uma chave aleatória; o servidor troca a chave por um cookie lume_sessao (HttpOnly, SameSite=Strict). A API e as páginas exigem esse cookie, então sites abertos no navegador não conseguem usar a API.
  • Host e origem conferidos: pedidos com outro Host (DNS rebinding) ou, nos que alteram dados, outra Origin são recusados. Política de conteúdo (CSP): só scripts do próprio aplicativo; links externos abrem no navegador padrão.
  • HTML dos DOCX: passa por uma lista de permissões do jsoup; imagens externas não carregam e as internas só saem da pasta do próprio documento. Arquivos maliciosos: DOCX lido com limites por parte e no total (contra zip bomb), sem DTD nem entidades externas; PDF com memória limitada e tempo limite.
  • Segredos: chave de API e segredos de webhook cifrados pelo cofre do Windows (DPAPI). Webhooks: só endereços http ou https, com assinatura HMAC opcional e tempo limite de 10 s. Abrir pasta: /desktop/open-path só abre caminhos que existem.

O código-fonte está todo no repositório. Para rodar a partir dele você precisa do JDK 21, do Maven 3.9 e do Git; o Node.js só é usado no teste de interface e o Python só para gerar estes manuais.

cd Document-Library-Desktop
mvn spring-boot:run                                              # compila e abre o Lume (janela no Edge)
mvn spring-boot:run -Dspring-boot.run.arguments=--sem-janela     # só o servidor

Em desenvolvimento, a pasta de dados é a mesma do aplicativo empacotado. Para usar outra, defina LUME_DATA_DIR antes de rodar (no PowerShell: $env:LUME_DATA_DIR="C:\temp\lume"). Capítulo 11

Solução de problemas

Os casos mais comuns e o que fazer. O arquivo lume.log, na pasta de dados, registra o que aconteceu em cada abertura; Ferramentas → Verificar a biblioteca confere o banco e os arquivos.

SintomaO que fazer
O Windows bloqueia o Lume.exeClique em Mais informações → Executar assim mesmo. Se o antivírus apagar o arquivo, restaure-o da quarentena e adicione uma exceção (executáveis portáteis sem assinatura às vezes são confundidos).
Demora para abrirA primeira abertura extrai o Java e o aplicativo (alguns segundos); as seguintes só sobem o Spring Boot. Em pendrives lentos, a primeira abertura demora mais.
A janela não apareceO Lume usa o Microsoft Edge. Atualize o Edge pelo Windows Update; sem ele, o Lume abre no navegador padrão. Veja o motivo em lume.log.
“O Lume já está aberto, mas não respondeu”Feche o processo javaw.exe do Lume no Gerenciador de Tarefas e abra de novo.
Um PDF ficou “Com erro”Veja a mensagem nos detalhes. Protegido por senha: abra num leitor de PDF, salve uma cópia sem senha e importe de novo. Erros passageiros: Ler o arquivo de novo (ou, para vários, a seleção em lote).
PDF sem descrição útil ou sem resposta no “Pergunte”PDFs digitalizados (só imagem) não têm texto; a descrição avisa isso. Passe o arquivo por um OCR e importe de novo.
A descrição ou a resposta não usa a IA externaConfira a chave e clique em Testar em Preferências. O motivo da queda para o modo local aparece em Sistema e no aviso abaixo da resposta.
Uma pasta monitorada não importaConfira se a pasta está ativa e existe (a linha mostra “Pasta não encontrada”), clique em Verificar agora e veja lume.log. Arquivos recusados uma vez só são tentados de novo quando mudam; arquivos só “na nuvem” do OneDrive precisam estar baixados.
O webhook mostra erroUse Testar e leia o código HTTP. 401/403: confira o endereço completo e o segredo; tempo esgotado: o serviço não respondeu em 10 s; endereços internos exigem que o computador alcance a rede deles.
A busca não acha algo que existeFerramentas → Reconstruir o índice de busca.
O banco cresceu muitoFerramentas → Limpar sobras e depois Otimizar o banco de dados.
“O banco foi criado por uma versão mais nova”Você abriu uma biblioteca com um Lume mais antigo. Use o executável mais novo.
Quero começar do zeroFaça um backup, feche o Lume e renomeie a pasta de dados (veja em Sistema). Na próxima abertura, uma biblioteca vazia é criada.
Levar para outro computadorFaça um Backup completo e restaure no outro computador (ou use o modo portátil). A chave de API e os segredos de webhook não vão junto: cadastre de novo.

Glossário

BM25
Fórmula de relevância usada pela busca (FTS5) e pelo “Pergunte ao documento”: termos raros e repetidos valem mais.
DPAPI
Cofre de dados do Windows; cifra a chave de API e os segredos de webhook para a sua conta.
FTS5
Busca em texto completo embutida no SQLite, com tokenizador sem acentos.
HMAC-SHA256
Assinatura que prova que um webhook veio do Lume: um código calculado com o segredo e o corpo.
jlink
Ferramenta do JDK que monta um Java reduzido só com os módulos usados.
Livro-caixa
O quadro de números das estantes (Quero ler, Lendo, Lidos) no cabeçalho da biblioteca.
Paleta de comandos
Caixa única aberta com Ctrl K para ir a telas, executar ações e achar documentos.
Pasta monitorada
Pasta cujos PDFs e DOCX novos entram sozinhos na biblioteca.
SHA-256
Impressão digital do conteúdo do arquivo; impede o mesmo arquivo duas vezes.
SSE
Server-Sent Events: o canal pelo qual o núcleo avisa a janela de cada mudança.
Trecho
Pedaço de 400 a 700 caracteres do texto, com a página, usado nas respostas do “Pergunte”.
Webhook
Endereço que recebe um aviso em JSON quando algo acontece no Lume.
